## Section 1 of 24 — Introduction to Machine Learning

### The three nested terms

| Term | Plain-English meaning | Example |
| --- | --- | --- |
| Artificial intelligence (AI) | The broad effort to make a system perform tasks associated with intelligence, such as interpreting language, recognizing objects, reasoning, or making decisions. | A rule-based troubleshooting expert system or an image-recognition service. |
| Machine learning (ML) | A way to build AI behavior by fitting a model to examples, rather than writing every decision rule by hand. | A spam filter trained on labeled messages. |
| Deep learning (DL) | A family of ML methods that uses neural networks with multiple layers to learn useful representations from data. | A convolutional network that learns visual patterns in images. |

Read the relationship as **deep learning is inside machine learning, and machine learning is inside AI**. The words are not interchangeable. A hand-written rule engine may be AI without being ML. A decision tree is ML without being deep learning. A neural network is not automatically *deep* just because it has the word “network” in its name; depth refers to multiple learned layers. The nested-circle picture in HTB is a teaching aid, not a claim that every intelligent behavior fits one fixed taxonomy.

For a data-engineering analogy, think of AI as the overall product capability (“classify suspicious events”), ML as a component that learns a mapping from historical records, and DL as one possible model family for that component. A production system may also contain non-ML rules, databases, APIs, human review, and monitoring. The model is not the whole application.

### Three ways a learning problem can provide feedback

1. **Supervised learning:** each training example includes a desired answer, or *label*. For email filtering, an example is a message plus “spam” or “not spam.” Training adjusts a model so its predictions better match those labels. Classification predicts a category; regression predicts a number. HTB introduces the category here and teaches individual algorithms later.
2. **Unsupervised learning:** examples arrive without those answer labels. The model looks for structure such as groups, unusual points, or lower-dimensional representations. A cluster of similar network events is a pattern, not automatically an attack. A human or a separate process must interpret what the pattern means.
3. **Reinforcement learning:** an *agent* chooses an action, the *environment* changes, and the agent receives a reward or penalty. Over many interactions it learns a *policy*—a rule for choosing actions in situations. This differs from being handed the correct action for every example. A game-playing agent learning from wins and losses is the course's intuitive example.

The easiest question to ask is: **Where does the feedback come from?** A supplied answer means supervised learning; no supplied answer means unsupervised learning; rewards after actions mean reinforcement learning. Real systems may combine these approaches, but keeping the basic cases separate will help when we reach their algorithms.

### What deep learning adds

Traditional ML often depends on people choosing useful input features—for instance, message length, sender reputation, and the presence of suspicious phrases. A deep network can learn intermediate features from rawer inputs. In an image system, early layers may react to edges or textures; later layers combine those responses into more complex shapes. “Early” and “later” describe processing stages, not a guarantee that every neuron has a neat human-readable meaning.

HTB names convolutional neural networks (CNNs) for images, recurrent neural networks (RNNs) for sequences, and transformers for language. Treat these as architecture families optimized for different data relationships, not as rules that restrict each family to only one task. “End-to-end” training means the final task's learning signal can adjust multiple stages together; it does not mean data collection, validation, deployment, and security happen automatically.

### Cybersecurity bridge (additional context)

- A **false negative** is a real threat that a detector misses. A **false positive** is benign activity that it flags. These errors have different costs: a missed intrusion can be damaging, while too many false alerts can overwhelm analysts.
- A model can learn only from the examples and labels it receives. An attacker who changes training records or labels may contaminate what it learns; that is a preview of **data poisoning**. An attacker who changes an input at prediction time to evade a trained detector is attempting **evasion**. Later path modules examine these attacks directly.
- Unsupervised anomaly detection asks “does this differ from the usual pattern?” It does **not** answer “is this malicious?” A new legitimate deployment can look anomalous, and a careful attacker can look ordinary.
- Reinforcement learning optimizes the stated reward. If the reward is a poor stand-in for the real safety objective, an agent may find a high-scoring but unwanted behavior. Security review must examine the reward definition and what the agent can control.

### Check your understanding

- A fixed list of hand-written fraud rules: potentially AI, but not ML just because it makes decisions.
- A decision tree trained on labeled fraud cases: ML and supervised learning, but not DL.
- Grouping unlabeled traffic records by similarity: unsupervised ML; the groups still need interpretation.
- A multi-layer neural network trained to identify objects in labeled images: supervised DL (and therefore also ML and AI).

## Section 2 of 24 — Mathematics Refresher for AI

HTB presents this page as a **reference**, not a test of mathematical fluency. We will return to these symbols when an algorithm needs them. The translation pattern below is: **say it aloud → identify each part → state the whole idea in plain English → calculate a small example**. In code blocks on the HTB page, `*` means multiplication; in formulas, a centered dot or adjacency may mean the same thing. A vector is an ordered list of numbers, and a matrix is a rectangular table of numbers.

### Addresses, powers, functions, and sums

- `$x_t$` is **“x sub t.”** The subscript `t` is an index or address, commonly a time step. If a sensor's readings are `[10, 13, 12]`, then with time steps `1, 2, 3`, `x_2 = 13`. A subscript is not multiplication by `t`. HTB's example also contains a vertical bar in `$q(x_t\mid x_{t-2})$`; read that bar **“given.”** It describes a quantity concerning the current value given a value two steps earlier. The page writes `$x_t=q(x_t\mid x_{t-2})$`, but those sides need not have the same type: a reading is a value, while `q(...)` may denote a probability or model output. Treat that line as an illustration of indexing, not a general identity.
- `$x^n$` is **“x to the n-th power.”** The superscript tells us to multiply `x` by itself `n` times when `n` is a positive integer. `$3^2=3\times3=9$` is “three squared equals nine.” Do not confuse a superscript with a subscript: `$x_2$` selects an item; `$x^2$` squares a value.
- `$f(x)$` is **“f of x.”** `f` is a function and `x` is its input. If `$f(x)=x^2+2x+1$`, then `$f(2)=2^2+2(2)+1=9$`. In programming terms, a function maps an input to an output; mathematical notation often leaves its implementation unspecified.
- `$\sum_{i=1}^{n} a_i$` is **“the sum from i equals one to n of a sub i.”** `i` is a loop counter, `a_i` is the item at index `i`, `1` is the first index, and `n` is the last. The whole expression means add every listed item. For `$a_1=2,a_2=4,a_3=6$`, `$\sum_{i=1}^{3}a_i=2+4+6=12$`. This is the mathematical version of a loop that accumulates a total.
- `$1/x$` is **“one over x,”** the reciprocal of nonzero `x`. `$1/5=0.2$`; division by zero is undefined. The dots in `$a_1+a_2+\cdots+a_n$` are read **“and so on”**—they indicate the same pattern continues, not an extra number.
- `max(4,7,2)=7` is **“the maximum of four, seven, and two is seven”;** `min(4,7,2)=2` is the corresponding minimum. The comparison signs `≥`, `≤`, `=`, and `≠` read **greater than or equal to**, **less than or equal to**, **equals**, and **not equal to**. Python writes these as `>=`, `<=`, `==`, and `!=` when testing values; `=` in Python is assignment, so do not copy mathematical equality syntax blindly into code.

### Measuring a vector's size: norms

Let `$v=(3,4)$`, a two-component vector. Bars around a number mean absolute value: `$|-4|=4$`. Double bars around a vector denote a *norm*, a rule that assigns it a nonnegative size.

- `$\lVert v\rVert_2=\sqrt{v_1^2+v_2^2}$` is **“the L-two norm of v equals the square root of v sub one squared plus v sub two squared.”** Each `v_i` is one component, squaring removes its sign and emphasizes larger components, the sum combines them, and the square root returns a length in the original units. For `(3,4)`, `$\sqrt{3^2+4^2}=\sqrt{25}=5$`. The complete idea is straight-line distance from the origin.
- `$\lVert v\rVert_1=|v_1|+|v_2|$` is **“the L-one norm of v equals the absolute value of v sub one plus the absolute value of v sub two.”** It totals the sizes of individual changes: `$|3|+|4|=7$`.
- `$\lVert v\rVert_\infty=\max(|v_1|,|v_2|)$` is **“the L-infinity norm of v equals the maximum absolute component.”** It measures the single largest component: `$\max(3,4)=4$`.

These are **different questions** about the same vector: total absolute movement, straight-line movement, and worst single-coordinate movement. In later evasion attacks, the vector may be a perturbation `$\delta=x'-x$`—read **“delta equals x-prime minus x”**—so choosing a norm changes what “small change” means. Note that *squared* L2, `$\lVert v\rVert_2^2=v_1^2+v_2^2=25$`, is **not** the L2 norm itself (`5`).

### Matrices without the mystique

For `$A=\begin{bmatrix}1&2\\3&4\end{bmatrix}$` and `$v=\begin{bmatrix}5\\6\end{bmatrix}$`, `$Av=\begin{bmatrix}17\\39\end{bmatrix}$` reads **“A times v equals the column vector seventeen, thirty-nine.”** Each output entry is a row's dot product with `v`: first row `$1(5)+2(6)=17$`; second row `$3(5)+4(6)=39$`. This is not component-by-component multiplication. `A` has shape `2 × 2`, `v` has shape `2 × 1`, and the result has shape `2 × 1`; the inner dimensions must agree.

If `$B=\begin{bmatrix}5&6\\7&8\end{bmatrix}$`, then `$AB=\begin{bmatrix}19&22\\43&50\end{bmatrix}$` is **“A times B.”** Each output entry combines one row of `A` with one column of `B`; for instance, the top-left entry is `$1(5)+2(7)=19$`. The entire operation composes two linear transformations. Order matters: in general `$AB\ne BA$`—read **“A B is not equal to B A.”**

- `$A^T$` is **“A transpose.”** Rows become columns: `$A^T=\begin{bmatrix}1&3\\2&4\end{bmatrix}$`. Transposing changes a `rows × columns` shape into `columns × rows`; it does not change the values themselves.
- `$A^{-1}$` is **“A inverse.”** It is a matrix that undoes multiplication by `A`: `$A^{-1}A=I$`, read **“A inverse times A equals the identity matrix.”** The identity `I` acts like `1` for matrix multiplication. Not every square matrix has an inverse. The course's example has `$A^{-1}=\begin{bmatrix}-2&1\\1.5&-0.5\end{bmatrix}$`.
- `$\det(A)$` is **“the determinant of A.”** For a `2 × 2` matrix `[[a,b],[c,d]]`, calculate `$ad-bc$`. For our `A`, `$1(4)-2(3)=-2$`. A zero determinant means a square matrix has collapsed some direction and cannot be inverted. The sign also encodes orientation; it is not a probability or model score.
- `$\operatorname{tr}(A)$` is **“the trace of A.”** Add its main-diagonal entries: `$1+4=5$`. This is a different summary from the determinant.

`$Av=\lambda v$` is **“A times v equals lambda times v.”** `λ` (lambda) is a scalar *eigenvalue*; nonzero `v` is an *eigenvector*. The complete statement says that applying `A` to this particular direction merely stretches, shrinks, or flips it without turning it into a new direction. With `$A=\operatorname{diag}(2,3)$` and `$v=(1,0)$`, `$Av=(2,0)=2v$`; therefore `v` is an eigenvector with eigenvalue `2`. This idea later helps explain principal component analysis (PCA), which finds directions that summarize variation in data.

### Sets and logical comparisons

For a set `$S=\{1,2,3\}$`, `$|S|=3$` is **“the cardinality of S is three”**—the number of distinct elements, not their numeric sum. Set bars and absolute-value bars look alike; context tells you whether you are counting a set or measuring a number.

Let `$U=\{1,2,3,4,5\}$` be the universe, `$A=\{1,2,3\}$`, and `$B=\{3,4\}$`. `$A\cup B=\{1,2,3,4\}$` reads **“A union B”**: elements in either set. `$A\cap B=\{3\}$` reads **“A intersection B”**: elements in both. `$A^c=\{4,5\}$` reads **“A complement”**: elements in the stated universe `U` but not in `A`. Without an explicit universe, “everything not in A” is ambiguous. In security operations, these can represent all alerts, alerts matching two rules, or events excluded by a rule.

### Logs and exponentials

`$\log_2(8)=3$` is **“log base two of eight equals three.”** It asks: *two to what power gives eight?* Since `$2^3=8$`, the answer is `3`. Logs turn repeated multiplication into addition and are useful when representing probabilities or information on a manageable scale.

`$\ln(e^2)=2$` is **“the natural log of e squared equals two.”** `e` is approximately `2.718`; `ln` means log base `e`, so it reverses raising `e` to a power. `$e^2\approx7.389$` is **“e squared is approximately seven point three eight nine.”** A base-two exponential `$2^x$` and a base-`e` exponential `$e^x$` grow at different rates, but both undo the corresponding logarithm. We will revisit `ln` when training objectives use log probabilities.

### Probability and spread

`$P(X\mid Y)$` is **“the probability of X given Y.”** The bar means *conditioned on*, not division. The complete idea is: after learning `Y` occurred, how likely is `X`? Importantly, `$P(\text{attack}\mid\text{alert})$` is not `$P(\text{alert}\mid\text{attack})$`. Suppose 1,000 events contain 10 attacks; a detector catches 9 attacks and raises 99 false alerts. Among the 108 alerts, only 9 are attacks, so the first probability is `$9/108\approx8.3\%$`. This **base-rate effect** matters when assessing real alert quality.

`$E[X]=\sum_i x_iP(X=x_i)$` is **“the expected value of X equals the sum over i of x sub i times the probability that X equals x sub i.”** For each possible outcome, multiply the outcome by its chance and add. If `$X=1$` with probability `0.25` and `$X=0$` with probability `0.75`, then `$E[X]=1(0.25)+0(0.75)=0.25$`. This is a probability-weighted average, not a promise that any single observation will equal `0.25`.

`$\operatorname{Var}(X)=E[(X-E[X])^2]$` is **“the variance of X equals the expected value of the squared difference between X and its expected value.”** Subtract the mean, square the distance, then average across outcomes. For the same `0/1` example, `$\operatorname{Var}(X)=0.75(0-0.25)^2+0.25(1-0.25)^2=0.1875$`. Variance is in *squared units*. `$\sigma(X)=\sqrt{\operatorname{Var}(X)}\approx0.433$` is **“sigma of X equals the square root of variance”**—the standard deviation, back in the original units.

`$\operatorname{Cov}(X,Y)=E[(X-E[X])(Y-E[Y])]$` is **“the covariance of X and Y equals the expected product of their deviations from their means.”** Positive covariance means they tend to move together; negative means they tend to move oppositely. `$\rho(X,Y)=\operatorname{Cov}(X,Y)/(\sigma(X)\sigma(Y))$` is **“rho of X and Y equals covariance divided by the product of their standard deviations.”** This standardized value lies from `-1` to `1` when both standard deviations are nonzero. For equally likely paired observations `(1,2)` and `(2,4)`, covariance is `0.5`, the standard deviations are `0.5` and `1`, and correlation is `$0.5/(0.5\times1)=1$`: a perfect positive linear relationship in this tiny example. Correlation does not by itself prove causation.

### Why these symbols matter to an AI red teamer

Norms quantify perturbations; matrix products describe neural-network layers; eigenvectors underpin PCA; conditional probabilities help interpret detector alerts; expectations and variance summarize uncertain outcomes. The symbols are compression for these ideas. Whenever a later formula looks intimidating, expand it into the same four steps used here: pronounce it, identify its parts, explain its purpose, and insert small numbers before looking at code.

## Section 3 of 24 — Supervised Learning Algorithms

This section defines the workflow that the following algorithm sections will instantiate. **Supervised** means that each example has a supplied answer. The learning task is to infer a reusable relationship, not to memorize a lookup table of training rows.

### A training record and the prediction loop

In the notation we will use to unpack HTB's prose, a training record is `$(x_i,y_i)$`—say **“the pair x sub i, y sub i.”** `i` identifies a row; `$x_i$` is that row's input features; `$y_i$` is its known label. A simple security row might have features such as message length, number of links, and sender reputation, with a label of phishing or benign. In data-engineering terms, features are columns available at decision time, while labels are the historical outcomes we want to learn to predict.

Write a model prediction as `$\hat y_i=f_\theta(x_i)$`: say **“y-hat sub i equals f sub theta of x sub i.”** The hat marks a *predicted* answer rather than the observed `$y_i$`; `$f$` is the model; `θ` (theta) represents its adjustable parameters. The complete sentence is: “With its current settings, the model turns row `i`'s features into a predicted label or value.” **Training** adjusts `θ`; **prediction** applies the learned settings to a new row. This notation is a learning aid for HTB's description, not a formula that HTB asks us to code in this section.

- **Classification** predicts a category: phishing versus benign, malware family A versus B, or cat versus dog.
- **Regression** predicts a numerical quantity: expected response time, transaction amount, or house price. A model's *score* for a category can be numeric even when the final task is classification; the task type depends on the desired output.

### Training, evaluation, and generalization

The basic flow is **collect labeled examples → separate training from evaluation data → fit parameters on training examples → evaluate on unseen examples → deploy and monitor**. The *training set* teaches the model. A *validation set* helps select settings and compare versions. A final *test set* estimates performance after those choices are fixed. Repeatedly looking at and tuning against the test set turns it into another validation set, giving an overoptimistic estimate. In time-ordered security data, a chronological split may be more honest than a random split: future campaigns must not leak into the past.

**Generalization** means performing well on new cases, not merely on records already seen. **Overfitting** is learning training-specific noise or quirks: training performance is excellent but new-case performance drops. **Underfitting** is failing to capture an important pattern at all: both training and new-case performance are poor. A model that memorizes attacker IPs from last month's logs might overfit and miss a new attacker using new infrastructure. A model that only checks message length might underfit a phishing problem.

**Cross-validation** repeatedly rotates which subset is held out: in five-fold cross-validation, train on four folds and evaluate on the fifth, then rotate through all five. This gives multiple estimates instead of trusting one arbitrary split. It does not cure leakage: near-duplicate samples, events from the same incident, or later events can still appear on both sides unless groups and time are respected.

HTB distinguishes *prediction* from the broader word *inference*. In applied ML, “model inference” often simply means running a trained model to obtain a prediction; in statistics, “inference” can mean estimating or explaining underlying relationships. Ask which sense a speaker means. Explaining a model's correlation is not the same as proving a causal relationship.

### Security evaluation: why accuracy alone can deceive

Consider 1,000 events: 10 are real attacks and 990 are benign. A detector catches 8 attacks, misses 2, and falsely alerts on 12 benign events. Read the four counts as follows:

| Actual versus predicted | Predicted attack | Predicted benign |
| --- | ---: | ---: |
| Actual attack | 8 **true positives** (TP) | 2 **false negatives** (FN) |
| Actual benign | 12 **false positives** (FP) | 978 **true negatives** (TN) |

- `$\text{Accuracy}=(TP+TN)/(TP+TN+FP+FN)$` is **“accuracy equals true positives plus true negatives, divided by all cases.”** It measures the fraction of all correct decisions: `$(8+978)/1000=98.6\%$`. That sounds excellent, yet many alerts are wrong. A detector that always said “benign” would achieve `99%` accuracy here while catching **zero** attacks.
- `$\text{Precision}=TP/(TP+FP)$` is **“precision equals true positives divided by all predicted positives.”** Of the events this model called attacks, how many were really attacks? `$8/(8+12)=40\%$`. Six out of ten alerts waste an analyst's time.
- `$\text{Recall}=TP/(TP+FN)$` is **“recall equals true positives divided by all actual positives.”** Of the real attacks, how many were caught? `$8/(8+2)=80\%$`. The remaining 20% slipped through.
- `$F_1=2PR/(P+R)$` is **“F-one equals two times precision times recall, divided by precision plus recall.”** Here `P` means precision and `R` means recall; the result is `$2(0.4)(0.8)/(0.4+0.8)\approx0.533$`. It is a *harmonic* mean: a low value in either ingredient pulls the score down. If both `P` and `R` are zero, define F1 as zero in this simple setting.

These formulas are added to make HTB's metric names concrete. They describe different operational questions, so choose metrics based on the cost of missed attacks versus false alerts. A single number never replaces examining the confusion matrix, class frequency, and the decision threshold.

### Regularization: discouraging an over-complex fit

HTB introduces **regularization** as adding a complexity penalty to the training loss. A generic objective can be written `$L_{\text{total}}(\theta)=L_{\text{data}}(\theta)+\lambda R(\theta)$`: say **“L-total of theta equals L-data of theta plus lambda times R of theta.”** `$L_{\text{data}}$` measures prediction mistakes, `$R$` measures model complexity, and `λ` (lambda) controls how strongly to penalize complexity. The complete idea is “fit the examples, but pay a price for a model whose parameters become too large or complicated.” This equation spells out HTB's prose; the course does not implement it yet.

For coefficient vector `$w=(w_1,\ldots,w_n)$`, an **L1 penalty** is `$R_1(w)=\sum_i|w_i|$`: say **“R-one of w equals the sum over i of the absolute value of w sub i.”** With `$w=(2,-3)$`, the penalty is `$|2|+|-3|=5$`. An **L2-squared penalty** is `$R_2(w)=\sum_iw_i^2$`: say **“R-two of w equals the sum over i of w sub i squared.”** For the same vector it is `$2^2+(-3)^2=13$`. L1 can encourage some coefficients to become exactly zero; L2-squared discourages large coefficients smoothly. These are penalties on **model parameters**. Later adversarial-attack norms often measure an **input perturbation** instead—same mathematical shapes, different objects and purposes.

### Security implications beyond the course's introductory list

- **Label quality:** if “benign” labels actually include undiscovered attacks, the training target is noisy. An attacker deliberately corrupting examples or labels is attempting **data poisoning**.
- **Feature availability:** a feature computed using facts discovered *after* an incident cannot be used by a real-time detector. Including it during training is **data leakage** and can make the model appear far better than it will be in production.
- **Distribution shift:** attackers change tooling and infrastructure, and legitimate traffic also changes. Monitor performance after deployment; yesterday's cross-validation score is not a permanent guarantee.
- **Evasion:** an adversary can modify an input at prediction time to cross the model's decision boundary while preserving the attack's function. This is distinct from poisoning training data.

This section is conceptual. We keep the examples in prose and arithmetic, then reserve annotated training code for the specific algorithms that HTB introduces next.

## Section 4 of 24 — Linear Regression

Linear regression is the first concrete model in the supervised-learning sequence. The label is a **number**, not a category. HTB uses house price and size as an intuition; our small companion notebook uses a synthetic request-size/latency example. That example demonstrates the arithmetic, not a realistic performance model or a security detector.

### One input: a line with two adjustable settings

HTB writes `$y=mx+c$`. Say **“y equals m times x plus c.”** `x` is the input feature, `m` is the *slope*, and `c` is the *intercept*. In prediction notation, it is clearer to write `$\hat y=mx+c$`—**“y-hat equals m times x plus c”**—because the actual observed `y` may differ from the line's prediction. The whole equation says: start with a baseline prediction `c`, then add `m` units for each unit of `x`. For `$m=2$` and `$c=1$`, at `$x=3$` the prediction is `$\hat y=2(3)+1=7$`. If `m` were negative, predictions would fall as `x` rises. The intercept may be mathematically necessary even when `x=0` is outside the meaningful data range; do not interpret it as a real-world zero-input measurement without checking that range.

This is a model assumption, not a law of nature. A straight line assumes a one-unit increase in `x` changes the prediction by the same amount throughout the modeled range. Security measurements often violate that assumption: traffic can saturate a service, so latency may bend upward at high load. Extrapolating far beyond training values is especially risky.

### Several inputs: contributions add together

HTB writes `$y=b_0+b_1x_1+b_2x_2+\cdots+b_nx_n$`. Say **“y equals b sub zero plus b sub one times x sub one plus b sub two times x sub two, and so on through b sub n times x sub n.”** `x_i` is feature `i`; `b_i` is that feature's coefficient; `b_0` is the intercept. For a prediction, read the left side as `y-hat`. The whole equation says to add a baseline to each feature's weighted contribution. For `$\hat y=2+3x_1-4x_2$`, inputs `$x_1=2$` and `$x_2=1$` produce `$2+3(2)-4(1)=4$`. Here `b_2=-4` means that increasing `x_2` by one changes the prediction by `-4` **if `x_1` is held fixed**. It does not prove that changing `x_2` causes the outcome to change: correlated features and omitted variables complicate that interpretation.

There is still no multiplication *between* features in HTB's equation. A line can have many input columns and still be “linear” in its coefficients. More features do not automatically make it more accurate on new data; they can also increase leakage and overfitting risk.

### Ordinary least squares: choose the best-fitting settings

For row `i`, write `$r_i=y_i-\hat y_i$`: say **“r sub i equals y sub i minus y-hat sub i.”** `r_i` is the *residual*, the signed gap from the observed value to the prediction. A positive residual means the model predicted too low; a negative one means it predicted too high. For a true value `5` and prediction `4`, the residual is `1`.

The residual sum of squares is `$RSS(m,c)=\sum_{i=1}^{N}(y_i-(mx_i+c))^2$`. Say **“R-S-S of m and c equals the sum from i equals one to N of y sub i minus open-parenthesis m times x sub i plus c close-parenthesis, all squared.”** `N` is the number of training rows; the inner subtraction is that row's residual; the square makes it nonnegative and makes a large miss count disproportionately; the sum produces one score for a candidate line. The whole equation says: *add up the squared prediction errors across every training row*. OLS chooses `$\operatorname*{arg\,min}_{m,c}RSS(m,c)$`—say **“the values of m and c that minimize R-S-S.”** `arg min` returns the **settings** that make the score smallest, not the smallest score itself.

Try three observations: `$(x,y)=(1,2),(2,3),(3,5)$`. The candidate line `$\hat y=x+1$` predicts `2, 3, 4`, so its residuals are `0, 0, 1` and `RSS=0^2+0^2+1^2=1`. OLS instead finds `$m=1.5$` and `$c=1/3$`. Its predictions are `$11/6,10/3,29/6$`; residuals are `$1/6,-1/3,1/6$`; and `RSS=1/36+1/9+1/36=1/6`, smaller than `1`. The line does not pass through every observation, because the goal is to minimize the **total** squared error.

For many features, the same idea applies: adjust all the `b` coefficients to minimize squared residuals. The companion notebook uses `numpy.linalg.lstsq`, a standard numerical least-squares solver, for this tiny example. That solver is a practical implementation choice, **not** code supplied by HTB in this section. We avoid teaching an explicit matrix inverse as the default algorithm; numerical solvers are typically safer and more stable.

### Assumptions and what happens when they fail

HTB lists four assumptions. **Linearity** means the conditional mean of the target is adequately represented by the additive straight-line formula. **Independence** means rows' errors are not systematically tied together; repeated measurements from one host or incident may violate it. **Homoscedasticity**, pronounced **“ho-mo-skeh-DAS-tiss-ity,”** means residual spread is roughly constant across the range of fitted values. If high-load measurements have much wider errors, uncertainty is not constant. **Normality** refers to residual/error distribution and is especially relevant to classical confidence intervals and significance tests; an imperfect bell shape does not automatically make point predictions useless. These are modeling assumptions to *check*, not properties guaranteed by calling an OLS function.

For a security use case, a small training RSS does not prove the model works on a new campaign or system. Inspect residuals, evaluate on held-out data, and check that input features are available at prediction time. A malicious or simply unusual high-leverage training point can pull an OLS line substantially because squaring emphasizes large residuals. That is a robustness concern beyond HTB's introductory explanation, not an attack we implement here.

## Section 5 of 24 — Logistic Regression

Despite the name, HTB introduces logistic regression as a **binary classifier**: the label is one of two categories, often encoded `0` and `1`. We still calculate a weighted sum of input features, but then convert it to a probability-shaped score and compare that score with a decision threshold. Our companion notebook uses invented email features to expose the calculation; it does not fit a real spam model or analyze private mail.

### From a weighted sum to a number between zero and one

HTB writes `$z=m_1x_1+m_2x_2+\cdots+m_nx_n+c$`. Say **“z equals m sub one times x sub one plus m sub two times x sub two, and so on through m sub n times x sub n, plus c.”** Each `x_i` is a feature, each `m_i` is its learned weight, and `c` is an intercept. This is the same additive structure we met in linear regression. Here `z` is a raw **score**, not yet a probability. For `$z=-2+1.2x_1+0.8x_2$` with `$x_1=1$` and `$x_2=1$`, `$z=0$`.

HTB's sigmoid is `$p(x)=\sigma(z)=1/(1+e^{-z})$`. Say **“p of x equals sigma of z equals one divided by one plus e to the negative z.”** `e` is about `2.718`; `e^{-z}` is an exponential; `σ` (sigma) names the sigmoid function. The whole equation means: transform any raw score on the number line into a value strictly between `0` and `1`. With `z=0`, `$e^0=1$`, so `$p=1/(1+1)=0.5$`. With `$z=\ln(4)\approx1.386$`—**“z equals the natural log of four”**—`$e^{-z}=1/4$` and `$p=1/(1+1/4)=0.8$`. Increasing `z` increases `p`, but the curve levels off near the endpoints.

`p(x)` is interpreted as the model's estimated probability of **class 1** *under the model and its training assumptions*. It is not automatically a well-calibrated real-world probability. If the training class balance differs from deployment, “0.8” may not correspond to an actual 80% frequency. Check calibration before treating that number as a risk estimate.

### Odds, log-odds, and why the boundary can stay flat

HTB lists linearity of **log-odds** as an assumption. For an event with probability `p`, the odds are `$p/(1-p)$`—say **“p divided by one minus p.”** At `$p=0.8$`, the odds are `$0.8/0.2=4$`, or four to one. The **log-odds** are `$\log(p/(1-p))$`—say **“the natural log of p divided by one minus p.”** For the sigmoid model, `$\log(p/(1-p))=z$`: **“the log-odds equal z.”** In other words, feature contributions add linearly to *log-odds*, even though their effect on the displayed probability is curved. This explains HTB's assumption more precisely than saying the probability itself must be a straight line.

At a threshold of `$0.5$`, the boundary is where `$p(x)=0.5$`, equivalently `$z=0$`. If `$z=m_1x_1+m_2x_2+c$`, then `$m_1x_1+m_2x_2+c=0$` is a **line** in a two-feature plot. In three features it is a **plane**; with more features, the same flat separator is called a **hyperplane**, pronounced **“HIGH-per-plane.”** “Hyper” just signals the dimension is too high to draw easily. The sigmoid is nonlinear in `z`, but applying it to an additive `z` does **not** by itself give a curved decision boundary in the original features. Feature transformations or interactions would be needed for those more complex shapes; HTB does not introduce them here.

### The threshold is a policy choice, not a different fitted model

Let `$\hat y=1$` when `$p(x)\ge t$` and `$\hat y=0$` otherwise. Say **“y-hat is one when p of x is greater than or equal to t; otherwise y-hat is zero.”** `t` is the chosen threshold. If the score is `0.8`, threshold `0.5` calls it positive; threshold `0.9` calls it negative. At exactly the threshold, our notebook uses `>=`, making the tie rule explicit. Raising a threshold usually produces fewer positive alerts: often fewer false positives, but potentially more false negatives. For spam filtering, false positives can hide legitimate mail; for intrusion detection, false negatives can miss attacks. Section 3's precision and recall explain the trade-off. A threshold is selected using validation data and operational costs, not because `0.5` is universally correct.

Changing the threshold moves the boundary. At threshold `$t=0.8$`, the boundary is `$z=\log(t/(1-t))=\log(4)\approx1.386$`, still a flat line/hyperplane for HTB's additive feature score. We do not retrain the weights merely to test a different threshold.

### Assumptions and security interpretation

HTB emphasizes a binary target, a linear relation in log-odds, enough representative data, and limited **multicollinearity**—pronounced **“multi-col-linearity.”** Multicollinearity means input features carry very similar information, making individual coefficients hard to interpret reliably. It does not necessarily prevent a useful prediction, but it weakens a story like “this one feature independently caused the decision.” Logistic regression can be extended beyond binary classification, but this section teaches the binary case; we do not implement extensions yet.

An adversary may attempt to change email features to cross the model's boundary while keeping the message persuasive; that is **evasion**. The toy notebook only computes scores for fixed examples and makes no attack. Likewise, a feature such as “number of suspicious words” is not a complete representation of an email. Any real security classifier needs leakage checks, representative labels, held-out evaluation, calibration, and review of false positives and false negatives.

## Section 6 of 24 — Decision Trees

HTB introduces decision trees for both **classification** (choose a category) and **regression** (predict a number). A **root node** asks the first question about all training rows; an **internal node** asks another question within one subset; a **leaf** supplies the result. A row is routed along one branch at each question until it reaches a leaf. In a security example, a small tree might ask whether a message has an attachment and then whether its sender is known. These are illustrative rules, not a real phishing policy.

Unlike logistic regression's flat boundary in the original features, successive threshold questions can create step-like regions and capture some non-linear patterns. The apparent readability of a small tree is valuable, but a deep tree with many branches can become hard to audit and can memorize noisy training rows. A split rule reflects association in the data, not proof that the tested feature caused the label.

### What “pure” means

A node is **pure** when all its rows share a class label. A mixed node contains several labels. Suppose a node `S` has 30 class-A rows and 20 class-B rows, so `$p_A=30/50=0.6$` and `$p_B=20/50=0.4$`. Say `$p_A$` **“p sub A,”** the fraction in class A; likewise for B. The full node has 50 rows; a split produces smaller *child* nodes. A good split leaves children that are, on average, less mixed than their parent.

HTB's Gini formula is `$G(S)=1-\sum_i p_i^2$`. Say **“G of S equals one minus the sum over classes i of p sub i squared.”** `S` is the node's rows, `i` ranges over its classes, and `p_i` is the class fraction. The complete idea is: measure how mixed the node is, with `0` meaning only one class. Here `$G(S)=1-(0.6^2+0.4^2)=0.48$`. The expression can also be interpreted as the chance of a mismatched label if a class is drawn using the node's class proportions. It is not a deployed model's observed error rate.

HTB's entropy formula is `$H(S)=-\sum_i p_i\log_2 p_i$`. Say **“H of S equals negative the sum over classes i of p sub i times log base two of p sub i.”** `log₂` asks what power of two gives its input. Since probabilities below one have negative logs, the leading minus makes the result nonnegative. The whole equation is another measure of uncertainty in the node's class labels. Here `$H(S)=-(0.6\log_2 0.6+0.4\log_2 0.4)\approx0.971$` bits. For a pure node the entropy is `0`; for an even binary split it is `1`. A zero-probability class contributes `0` by the mathematical limiting convention `$0\log_2 0:=0$`; code should skip that term rather than calculate `log₂(0)`.

Gini and entropy are alternatives, not numbers on the same absolute scale. A tree-building algorithm commonly chooses the candidate split with the largest *reduction* in its selected impurity measure. For regression trees, a variance or squared-error reduction can play a similar role; this section's worked arithmetic is classification-specific.

### How a proposed split earns information gain

HTB writes `$IG(S,F)=H(S)-\sum_v (|S_v|/|S|)H(S_v)$`. Say **“information gain of S from feature F equals entropy of S minus the sum over branch values v of the size of S sub v divided by the size of S, times entropy of S sub v.”** `$S_v$` is the subset sent down branch `v`; `$|S_v|$` is its row count; dividing by `$|S|$` weights a child by how many rows reach it. The whole equation says: *take the parent's uncertainty and subtract the average uncertainty left after splitting*. A tiny pure child should not count as much as a large mixed child.

HTB's example divides 50 rows as follows: branch `F=1` contains 20 A and 10 B (`30` rows), while branch `F=2` contains 10 A and 10 B (`20` rows). The parent contains 30 A and 20 B. We already found its entropy to be about `0.97095`. The first child's entropy is about `0.91830`; the evenly split child's entropy is `1`. The weighted child entropy is `$(30/50)(0.91830)+(20/50)(1)\approx0.95098$`. Therefore information gain is `$0.97095-0.95098\approx0.01997$` bits. Positive, but small: this particular split barely reduces uncertainty. The companion notebook reproduces those counts and checks the arithmetic; it does not claim this is the best possible feature without comparing other candidates.

### Growing and stopping the tree

Tree building repeats this process recursively: evaluate candidate feature tests at the current node, choose a useful split, partition its rows, then repeat within children. Stop when a node is pure, a maximum depth is reached, or too few rows remain to split reliably. Those limits are practical defenses against the **overfitting** introduced in Section 3. A leaf often predicts the majority training class for classification or the mean target for regression. Real libraries have additional choices such as minimum gain and pruning; HTB's page focuses on the core structure, so our notebook stops at scoring one candidate split.

The tennis example uses one-hot columns such as `Outlook_Sunny` and `Outlook_Rainy`: one categorical value is represented by several true/false fields. In a security dataset, these might instead encode event type or message origin. If several columns describe the same event, split explanations must be read in context. HTB correctly notes that trees do not require a straight-line relation or normally distributed features. “Handles outliers” is relative, not immunity: an unusual or poisoned record may still influence a split, particularly in a small node. Assess unseen-data performance and feature provenance before trusting a tree-based security decision.

## Section 7 of 24 — Naive Bayes

HTB moves from a tree's sequence of feature questions to a **probabilistic classifier**: start with how common a class is, then update that belief after observing evidence. The word *naive* refers to a simplifying assumption about features, not to the quality or safety of the prediction. The section teaches Bayes' theorem, one numerical medical-test example, the classification workflow, and the Gaussian/Multinomial/Bernoulli variants. The companion notebook calculates these examples but does not train a real mail filter.

### The direction of a conditional probability matters

HTB writes `$P(A\mid B)=P(B\mid A)P(A)/P(B)$`. Say **“the probability of A given B equals the probability of B given A times the probability of A, divided by the probability of B.”** The vertical bar `|` (written `\mid` in typesetting) means **“given”**: assume the event on its right has happened. `$P(A)$` is the *prior* chance of A, before the new evidence B. `$P(B\mid A)$` is the *likelihood* of seeing B when A is true. `$P(B)$` is the overall chance of seeing B. `$P(A\mid B)$` is the *posterior*: our updated chance of A after seeing B. The whole equation says to weigh the prior by how compatible the evidence is with A, then scale by how common that evidence is overall. `$P(B\mid A)$` and `$P(A\mid B)$` are **not interchangeable**.

HTB's example lets A mean “has the disease” and B mean “tests positive.” Prevalence is `$P(A)=0.01$`; sensitivity is `$P(B\mid A)=0.95$`; the false-positive rate is `$P(B\mid\neg A)=0.05$`. Say `$\neg A$` **“not A.”** Its probability is `$P(\neg A)=1-P(A)=0.99$`. The page calls the 95% figure “accuracy,” but *sensitivity* is more precise here: it tells us the positive-test rate among those who have the disease, not the test's overall accuracy.

To obtain the denominator, HTB uses `$P(B)=P(B\mid A)P(A)+P(B\mid\neg A)P(\neg A)$`. Say **“the probability of B equals the probability of B given A times the probability of A, plus the probability of B given not A times the probability of not A.”** This is the *law of total probability*: every positive test comes either from someone with the disease or someone without it. Substitute the values: `$P(B)=0.95(0.01)+0.05(0.99)=0.0095+0.0495=0.059$`. Then `$P(A\mid B)=0.0095/0.059\approx0.161$`, about **16.1%**. In a hypothetical group of 10,000, expect 100 with the disease and 95 true positives, plus 9,900 without it and 495 false positives. Among 590 positives, only 95 are true positives. This makes the low-base-rate effect tangible without changing HTB's arithmetic. These are expected counts, not a diagnosis of an individual.

### How a classifier combines features

Let `C` be a class (spam or not spam) and `$x_1,\ldots,x_n$` the observed features. Say `$x_i$` **“x sub i,”** feature number `i`. The classifier seeks `$P(C\mid x_1,\ldots,x_n)$`: **“the probability of class C given features x sub one through x sub n.”** The *conditional-independence* assumption means that, **once C is known**, knowing one feature does not change the modeled chance of another. That lets the model use `$P(C\mid x_1,\ldots,x_n)\propto P(C)\prod_{i=1}^nP(x_i\mid C)$`. Say **“the posterior for C is proportional to the prior for C times the product, over features i, of the likelihood of x sub i given C.”** `\propto` means **“proportional to”**: this computes a score for each class before dividing all scores by their sum to make probabilities. `\prod` (capital pi) means **“multiply all these terms,”** just as capital sigma `\sum` means add all terms. The complete idea is: score each class by its prior and by how plausible every observed feature is under that class, normalize, and choose the largest posterior.

For an illustrative **Bernoulli** (present/absent) example, suppose spam has prior `0.2`; not-spam has prior `0.8`. Given spam, `free` appears with probability `0.7` and `meeting` appears with probability `0.1`. Given not-spam, their probabilities are `0.1` and `0.6`. A message containing `free` but **not** `meeting` gets spam score `$0.2(0.7)(1-0.1)=0.126$` and not-spam score `$0.8(0.1)(1-0.6)=0.032$`. Dividing by `$0.126+0.032=0.158$` yields a spam posterior of about `0.797`. The factor `$1-0.1=0.9$` matters: a Bernoulli feature models **absence as well as presence**. These hand-chosen probabilities are teaching numbers, not estimates from HTB's dataset. Correlated words can violate the independence assumption, so this numerical posterior should not be mistaken for a calibrated production risk score.

### Match the variant to the feature representation

**Gaussian Naive Bayes** models continuous features with a bell-shaped conditional distribution for each class. **Multinomial Naive Bayes** is commonly used with discrete counts such as word frequencies. **Bernoulli Naive Bayes** uses binary present/absent features and accounts for both outcomes. These are alternative likelihood models under the same Bayes framework, not three successive stages of one algorithm. Which one is sensible depends on the data representation and how well its assumptions approximate the task. Estimating these probabilities needs enough representative training data; zero observed counts can cause a whole product to become zero, so implementations often use *smoothing*. HTB does not introduce a smoothing formula here, and the notebook does not add one.

For cybersecurity, an email classifier must also be evaluated for false positives (legitimate messages blocked), false negatives (malicious messages missed), class imbalance, shifting attacker language, and leakage from features unavailable when the decision is made. An attacker might deliberately replace “free” with other wording to reduce a word-based spam score; that is an evasion possibility, not an attack performed by this lesson's notebook. Bayes' theorem is about updating a model's probabilities, not a guarantee that its features or training labels are trustworthy.

## Section 8 of 24 — Support Vector Machines (SVMs)

An SVM is another supervised method for classification or regression. HTB concentrates on classification: choose a dividing boundary with the **widest margin**, meaning as much clearance as possible between the boundary and the nearest labeled points. This differs from logistic regression's probability-shaped output and Naive Bayes' posterior calculation. A basic SVM produces a signed decision score and class, not automatically a calibrated probability. A large training margin is a useful generalization principle, not a guarantee of performance on shifted or adversarial data.

### A flat boundary and the points that pin it down

HTB writes `$w\cdot x+b=0$` (its plain-text `w * x` means a vector **dot product**). Say **“w dot x plus b equals zero.”** `$x=(x_1,\ldots,x_d)$` is a point's `d` features; `$w=(w_1,\ldots,w_d)$` contains corresponding weights; `$w\cdot x=\sum_{j=1}^d w_jx_j$` means **“sum from feature j equals one to d of w sub j times x sub j.”** `$b$` is a bias or intercept. Together they produce a score `$s(x)=w\cdot x+b$`—**“s of x equals w dot x plus b.”** Zero means *on* the boundary; positive and negative scores lie on opposite sides. The weight vector points perpendicular to the boundary. A line in two features, plane in three, or flat separator in more dimensions is called a **hyperplane** (say **“HIGH-per-plane”**).

The **support vectors** are the closest training points on either side. They fix the location and width of the maximum-margin separator, hence “support.” If two classes have points at positions `$x=0$` and `$x=2$` on a number line, assign labels `-1` and `+1`. The boundary `$s(x)=x-1=0$` sits at `$x=1$`. The point at `0` has score `-1`; the point at `2` has score `+1`. Both are one unit from the boundary and are support vectors in this tiny hard-margin setup. A new point at `1.5` has score `0.5` and falls on the positive side, but its score is not a 50% probability.

### Read the hard-margin optimization carefully

HTB writes **minimize** `$\tfrac12\lVert w\rVert^2$` **subject to** `$y_i(w\cdot x_i+b)\ge1$` for every row `i`. Say the first part **“minimize one-half the squared L-two norm of w.”** The L-two norm `$\lVert w\rVert$` is the vector's Euclidean length; `$\lVert w\rVert^2=\sum_jw_j^2$` is its squared length. This is a **weight** norm, not an adversarial perturbation norm. Say the constraint **“y sub i times open-parenthesis w dot x sub i plus b close-parenthesis is greater than or equal to one.”** `$x_i$` is training row `i`; `$y_i\in\{-1,+1\}$`—**“y sub i belongs to the set negative one, positive one”**—is its class sign. Multiplying by `y_i` makes a correctly placed point's score positive for either class. The complete requirement is: *every training point must be correctly classified with a signed score of at least one*. Equality marks a point on a margin boundary; a negative signed score is misclassified.

Why does minimizing the length of `w` widen the gap? The perpendicular distance from a point to the hyperplane is `$|w\cdot x+b|/\lVert w\rVert$`—say **“the absolute value of w dot x plus b, divided by the length of w.”** For support vectors with scores `+1` and `-1`, each side's geometric clearance is `$1/\lVert w\rVert$`; the full gap is `$2/\lVert w\rVert$`. Smaller `\lVert w\rVert` therefore means a larger geometric margin *while the score-one constraints hold*. The factor `1/2` makes later derivatives cleaner but does not change the minimizer. The companion notebook checks HTB's constraint and these distances for the number-line example; it does not solve the optimization problem.

This is a **hard-margin** formula: it demands every training row meet the constraint and is feasible only when the classes can be separated in the chosen feature space. Real spam or intrusion datasets may overlap, contain mislabeled rows, or include outliers. A soft-margin SVM permits some violations with a penalty; HTB does not provide that optimization formula in this section, so we do not implement it. The page's description “robust to outliers” is relative and context-dependent: an extreme or mislabeled point can change the support vectors and boundary substantially. Scaling features matters too: if one feature is measured in huge units, its numerical range can dominate distances unless preprocessing is appropriate.

### What a kernel changes—and what it does not

If a straight boundary cannot adequately separate the classes in the original features, a **kernel** measures similarity as if points had been transformed to another feature space. HTB's “lift marbles off the table” metaphor describes this. It is more precise to say a kernel can compute the transformed-space dot product **without explicitly constructing every transformed coordinate**: `$K(x,z)=\phi(x)\cdot\phi(z)$`. Say **“K of x and z equals phi of x dot phi of z.”** `\phi` (say **“fee”** or **“phi”**) is a conceptual feature mapping; `K` returns their similarity in that mapped space. A flat separator there can correspond to a curved boundary in the original feature space. A kernel does not guarantee separability or a better model.

HTB names **polynomial**, **radial basis function (RBF)**, and **sigmoid** kernels. A polynomial kernel represents polynomial interactions; an RBF kernel gives nearby points greater similarity and can form flexible boundaries; a sigmoid kernel is related in shape to the logistic sigmoid but is not the same as logistic regression. The notebook uses `$K(x,z)=(x\cdot z)^2$`—say **“K of x and z equals x dot z, squared”**—to demonstrate one polynomial-kernel identity numerically. It is an extra transparent illustration of HTB's kernel idea, **not** an SVM training procedure. Kernel and parameter choices affect complexity and overfitting, so they must be assessed on held-out data.

For security, a classifier's margin is not automatically a proven adversarial-robustness bound. An attacker may alter several feasible input features to cross the boundary while preserving the malicious function; conversely, changes that look small in a standardized feature vector may be impossible in a real packet or message. Keep the feature representation, preprocessing, operational constraints, and false-positive/false-negative costs in view before translating geometry into claims about defense.

## Section 9 of 24 — Unsupervised Learning Algorithms

The supervised methods in Sections 4–8 learned from examples with known target labels. **Unsupervised learning** starts with feature rows that lack those target labels and searches for structure. HTB organizes the uses into **clustering** (group similar rows), **dimensionality reduction** (summarize many features with fewer), and **anomaly detection** (find rows that do not fit a chosen notion of normality). These goals are different: a cluster is not automatically a class label, and an unusual row is not automatically malicious. This overview does not yet specify or implement a clustering algorithm. Our companion notebook only compares the distance and scaling concepts that HTB names.

### Similarity depends on the question and the units

For two feature vectors `$x=(x_1,\ldots,x_d)$` and `$z=(z_1,\ldots,z_d)$`, **Euclidean distance** is `$d_2(x,z)=\sqrt{\sum_{j=1}^d(x_j-z_j)^2}$`. Say **“d-two of x and z equals the square root of the sum over features j of x sub j minus z sub j, squared.”** The subtraction is each coordinate's difference; squaring prevents positive and negative differences from cancelling; summing combines coordinates; the square root restores a straight-line length. For `$x=(1,2)$` and `$z=(4,6)$`, differences are `-3` and `-4`, so the distance is `$\sqrt{9+16}=5$`.

**Manhattan distance** is `$d_1(x,z)=\sum_{j=1}^d|x_j-z_j|$`. Say **“d-one of x and z equals the sum over features j of the absolute value of x sub j minus z sub j.”** Absolute values count each coordinate's change without allowing cancellation. For the same points it is `$3+4=7$`, like walking three blocks in one direction and four in another. These names echo L2 and L1 norms already seen: `$d_p(x,z)=\lVert x-z\rVert_p$`—say **“d sub p of x and z equals the L-p norm of x minus z.”** Here the norm measures *distance between feature rows*, not model coefficients or attack perturbations.

**Cosine similarity** is `$\operatorname{cosim}(x,z)=(x\cdot z)/(\lVert x\rVert_2\lVert z\rVert_2)$`. Say **“cosine similarity of x and z equals x dot z divided by the L-two length of x times the L-two length of z.”** The dot product measures directional alignment; dividing by both lengths removes the effect of overall magnitude. For `$x=(1,0)$` and `$z=(1,1)$`, the dot product is `1`, the lengths are `1` and `$\sqrt2$`, so similarity is `$1/\sqrt2\approx0.707$`. Larger cosine similarity indicates closer *direction* (for nonnegative count vectors it typically lies between zero and one). A zero vector has length zero, so its cosine similarity is undefined; code must handle that case rather than divide by zero. Cosine is a similarity, not a Euclidean distance, and the metrics can rank neighbors differently.

HTB correctly emphasizes **feature scaling**. If one column is in tens and another in tens of thousands, raw Euclidean or Manhattan distance will usually be dominated by the second column's numerical units, whether or not that feature deserves more importance. **Min–max scaling** maps a training feature's observed minimum to `0` and maximum to `1`; values from later data can fall outside that range. **Standardization** uses `$z_j=(x_j-\mu_j)/\sigma_j$`: say **“z sub j equals x sub j minus mu sub j, divided by sigma sub j.”** `$\mu_j$` (say **“mew sub j”**) is feature `j`'s training mean; `$\sigma_j$` (say **“SIG-ma sub j”**) is its training standard deviation. The result says how many training-standard-deviation units a value lies above or below the mean. A zero-variance column needs special handling. Fit these values on **training data only**, then apply the same transformation to validation, test, and deployed data; recomputing from the test set leaks information and changing scaling at inference changes the model's meaning. Scaling does not prove features are equally informative; it only changes their numerical influence.

### Structure may exist—or may be imposed by the method

**Clustering tendency** asks whether the data actually has group-like structure. A clustering algorithm can partition even a uniform cloud, but those partitions may lack real meaning. **Cluster validity** then asks whether the result is useful: *cohesion* means points within a cluster resemble one another, while *separation* means different clusters are distinct. HTB names the silhouette score and Davies–Bouldin index as possible summaries; neither makes a cluster a true category or proves causal structure. Business or security interpretation and held-out stability matter too.

**Dimensionality** is the number of recorded features. **Intrinsic dimensionality** is the smaller number of effective degrees of freedom that may underlie those features. If ten sensor columns all track roughly one physical quantity, the data can be recorded in ten dimensions but vary largely along one. Dimensionality reduction tries to preserve useful variation in fewer coordinates; what counts as “useful” depends on the downstream task. The **curse of dimensionality** describes several high-dimensional difficulties, including increasing sparsity and distance measures becoming less discriminating. More columns do not automatically mean more information.

An **outlier** is geometrically far from most observations under a chosen representation and metric. An **anomaly** is a deviation that matters for the task. A rare-but-authorized administrator action can be a geometric outlier without being an attack; a malicious event can resemble normal traffic and fail to appear as an outlier. Logs can also contain collection errors. Therefore an anomaly detector is an investigative signal, not a verdict: validate provenance, benign rare behavior, drift, and false-alert load. An adversary may deliberately blend into dense “normal” regions, while poisoning normal-data collection can change what the system considers ordinary.

## Section 10 of 24 — K-Means Clustering

K-means is the first concrete unsupervised algorithm in this module. Choose an integer `$K$`—say **“K,” the number of clusters**—and partition unlabeled points into `K` non-overlapping groups. A **centroid** (say **“SEN-troyd”**) is a group's coordinate-wise mean, not necessarily an observed row. The algorithm alternates assignment to the nearest centroid and updating each centroid to its assigned rows' mean. A row belongs to exactly one cluster in ordinary K-means. Cluster numbers are arbitrary identifiers, not discovered class names or security verdicts.

### One full assign-and-update cycle

HTB measures closeness with Euclidean distance `$d(x,c)=\sqrt{\sum_j(x_j-c_j)^2}$`. Say **“distance from x to c equals the square root of the sum over features j of x sub j minus c sub j, squared.”** This is the straight-line feature-space distance from a row `x` to a candidate centroid `c`; Section 9 unpacked its pieces. The assignment is `$a_i=\operatorname*{arg\,min}_{k\in\{1,\ldots,K\}}d(x_i,\mu_k)$`. Say **“a sub i equals the index k, among the K clusters, that minimizes the distance from x sub i to mu sub k.”** `\mu` is read **“mew”** and `\mu_k` is the centroid of cluster `k`. `arg min` returns the **winning cluster index**, not the distance. A tie needs a deterministic rule in code; our notebook chooses the lower index.

The update is `$\mu_k=(1/|C_k|)\sum_{i\in C_k}x_i$`. Say **“mu sub k equals one divided by the size of C sub k, times the sum of x sub i over rows i in cluster C sub k.”** `$C_k$` is the assigned row set, `$|C_k|$` its count, and the sum is coordinate-wise for vectors. The whole equation says: place each centroid at the arithmetic mean of its assigned rows. An empty cluster has no mean and needs a deliberate recovery policy; tiny examples can avoid one, while production implementations handle it explicitly.

For a one-feature toy dataset `$x=(0,1,9,10)$`, pick `$K=2$` and initial centroids `0` and `9`. Assignment puts `0,1` in the first group and `9,10` in the second. Updating moves centroids to `0.5` and `9.5`. Reassigning changes nothing, so this toy run has stabilized. Initialization matters: a different start can reach a different local solution. HTB says randomly select initial data points; real libraries often use more careful multi-start initialization such as k-means++, which is an implementation alternative, not a requirement introduced by this page.

### What the algorithm minimizes

The within-cluster sum of squares is `$WCSS=\sum_{k=1}^{K}\sum_{i\in C_k}\lVert x_i-\mu_k\rVert_2^2$`. Say **“W-C-S-S equals the sum over clusters k, then over points i in cluster k, of the squared L-two distance between x sub i and mu sub k.”** Each point contributes a squared Euclidean distance to its group's centroid; the complete equation measures how compact the assigned groups are. For the toy two-cluster result, `$WCSS=(0-0.5)^2+(1-0.5)^2+(9-9.5)^2+(10-9.5)^2=1$`. With `$K=1$`, the centroid is `5` and `$WCSS=25+16+16+25=82$`. This explains why the two-cluster partition fits the training points much more compactly. HTB's wording also mentions clusters being far from one another, but **ordinary K-means directly minimizes within-cluster squared distances**; separation is not a separate term in this objective.

The repeated assignment/update steps do not increase WCSS when executed with the usual squared-Euclidean objective and no unusual empty-cluster handling: assignment picks the nearest centroid, and the mean minimizes each cluster's squared distances. This does **not** guarantee the globally best partition because the result can depend on initialization. The companion notebook implements only the small one-dimensional iteration so each assignment and mean stays visible.

### Choosing K is a model-selection judgment

The **elbow method** plots WCSS against `K`. WCSS can only improve or stay the same as extra clusters are allowed, reaching zero at `$K=N$` when every one of `N` distinct points gets its own centroid. Therefore “choose the smallest WCSS” would trivially over-partition the data. An **elbow** is a point after which adding clusters buys much less reduction; it is a heuristic and can be ambiguous. In the toy data, the big drop from `82` to `1` makes `K=2` intuitive, but four points are too little to establish a general selection rule.

For a point `i`, let `$a(i)$` be its average distance to other points in its **own** cluster, and `$b(i)$` its lowest average distance to points in **another** cluster. Say `$a(i)$` **“a of i”** and `$b(i)$` **“b of i.”** A silhouette score is `$s(i)=(b(i)-a(i))/\max(a(i),b(i))$`: say **“s of i equals b of i minus a of i, divided by the larger of a of i and b of i.”** Near `+1` means its own cluster is much closer; near `0` means an ambiguous boundary; negative means another cluster is closer on average. For toy point `0`, `$a=|0-1|=1$` and `$b=(|0-9|+|0-10|)/2=9.5$`, so `$s=(9.5-1)/9.5\approx0.895$`. The notebook calculates this one score. Silhouette is undefined for a single cluster and has special conventions for singleton clusters; choosing the highest average score is a useful heuristic, not proof of semantic meaning.

HTB also asks us to use domain expertise. Too few clusters merge distinct behaviors; too many fragment them and raise operational cost. The common “round, similar-sized clusters” assumption is a rough fit to what squared Euclidean distance and arithmetic means favor. Long curved clusters or very unequal densities may be split poorly. K-means is sensitive to **feature units** (Section 9), outliers (means can be pulled), and initial centroids. In security telemetry, a cluster might group related events or hosts, but a cluster ID is not a threat label. Validate interpretations against known incidents, benign unusual behavior, drift, and the real cost of investigating alerts; consider whether feature changes an adversary can make would move an event across cluster boundaries.

## Section 11 of 24 — Principal Component Analysis (PCA)

**Principal Component Analysis**, “P-C-A,” reduces feature count by replacing original axes with new **perpendicular directions** ordered by how much variation the data shows along them. Unlike K-means, which assigns rows to groups, PCA gives each row new numerical coordinates. It is an **unsupervised** transformation: the target label does not tell PCA which variation is useful. HTB highlights visualization, feature extraction, and possible noise reduction. “Captures the most variance” is the precise goal; “preserves the most important information” is only justified when the relevant information happens to align with high-variance directions.

### Center, measure spread, and compare features

For values `$x_1,\ldots,x_n$` of one feature, the sample mean is `$\bar x=(1/n)\sum_{i=1}^n x_i$`: say **“x-bar equals one over n times the sum of x sub i from one to n.”** Centering subtracts this mean from every value, so the transformed feature averages to zero. Sample variance is `$s_x^2=(1/(n-1))\sum_i(x_i-\bar x)^2$`: say **“s sub x squared equals one over n minus one times the sum of x sub i minus x-bar, squared.”** Each squared gap contributes to the feature's spread. The `n-1` denominator is the standard sample-covariance convention used in the notebook; with a population convention, denominator `n` changes the numerical eigenvalues but not this example's directions.

For features `x` and `z`, sample covariance is `$\operatorname{cov}(x,z)=(1/(n-1))\sum_i(x_i-\bar x)(z_i-\bar z)$`. Say **“covariance of x and z equals one over n minus one times the sum of x sub i minus x-bar, times z sub i minus z-bar.”** Positive values mean the centered features often rise and fall together; negative values mean they tend to move oppositely; near zero means little *linear* co-variation. A covariance matrix `C` places each feature's variance on its diagonal and each pair's covariance off-diagonal. It is a compact description of the cloud's spread. Covariance is sensitive to units: dollars and counts can give very different numerical scales. HTB's workflow standardizes each feature first (Section 9's z-score) so unit ranges do not dominate. Centering alone can also be appropriate when original units should retain their relative importance; the choice is a modeling decision. Fit the transformation on training data only and reuse it on new rows.

Consider three two-feature points `$(1,1),(2,2),(3,3)$`. Their mean is `$(2,2)$`; centered rows are `$(-1,-1),(0,0),(1,1)$`. Using the sample denominator `$n-1=2$`, both feature variances are `1` and covariance is `1`, so `$C=\begin{bmatrix}1&1\\1&1\end{bmatrix}$`. Say **“C is the two-by-two matrix with one in every entry.”** The two features move together perfectly in this toy set: there are two recorded columns but only one direction of variation. To keep the arithmetic transparent, the notebook **centers but does not standardize** these equal-scale toy features; this differs from HTB's general recommended standardization step without contradicting its purpose.

### What the eigen-equation says

HTB writes `$Cv=\lambda v$`. Say **“C times v equals lambda times v.”** `v` is a nonzero direction vector, called an **eigenvector** (say **“EYE-gen-vector”**); `$\lambda$` is **“lambda,”** its eigenvalue. The equation says that applying the matrix `C` to this special direction changes only its length (or possibly flips its sign), by the factor `\lambda`; it does not turn it into an unrelated direction. For a covariance matrix, eigenvalues are nonnegative and, with unit-length eigenvectors, equal the variance measured along those directions. HTB's simpler matrix `$A=\begin{bmatrix}2&0\\0&1\end{bmatrix}$` sends `$v=(1,0)$` to `$(2,0)$`, so its eigenvalue is `2`: stretched by two along the x-axis. That illustrates the equation, while `C` is the specific matrix used by PCA.

For the toy covariance `$C=\begin{bmatrix}1&1\\1&1\end{bmatrix}$`, the first unit direction is `$v_1=(1,1)/\sqrt2$`—say **“v sub one equals one comma one, divided by square root of two.”** `$Cv_1=2v_1$`, so `$\lambda_1=2$`. The perpendicular direction `$v_2=(1,-1)/\sqrt2$` has `$Cv_2=0v_2$`, so `$\lambda_2=0$`. The first direction captures all the sample variance; the second captures none. The **sign** of an eigenvector is arbitrary: `(-1,-1)/√2` describes the same axis as `(1,1)/√2`, just with reversed coordinate signs. Code should not assert a particular sign from an eigensolver.

### Select directions, project, and understand loss

Sort directions by descending eigenvalue and keep the first `$k$` (say **“k,” the number of retained components**). HTB writes `$Y=XV$`: say **“Y equals X times V.”** `X` must be the **centered or standardized** rows used to compute `C`; `V` has the selected eigenvectors as columns; `Y` contains each row's new component scores. If `X` has `$n$` rows and `$d$` original features and `V` has `$d$` rows and `$k$` columns, `Y` has `$n$` rows and `$k$` scores. The whole operation projects each row onto the retained directions. In the toy example, the one-component scores are `$-\sqrt2,0,+\sqrt2$`: each centered row's dot product with `$v_1$`. Since the discarded direction has zero variance, adding the mean back after reconstructing from that one component exactly recovers all three toy points. Ordinary data rarely reconstructs exactly after reduction.

The explained-variance ratio of component `j` is `$r_j=\lambda_j/(\sum_\ell\lambda_\ell)$`. Say **“r sub j equals lambda sub j divided by the sum of all the lambdas.”** It is the fraction of total modeled variance captured by that direction. Here `$r_1=2/(2+0)=1$`, or 100%; the second is zero. HTB suggests choosing enough components to reach a threshold such as 95%, but that is a **heuristic**, not a guarantee of predictive or security utility. If all eigenvalues are zero, this ratio has a zero denominator and is undefined. Libraries often use **singular value decomposition**, “S-V-D,” on the centered data matrix for numerical stability rather than explicitly forming and eigendecomposing covariance; HTB names this as an alternative. Our tiny notebook uses an eigen-solver to expose the page's equation, not to prescribe a production numerical method.

PCA finds **linear** directions and is sensitive to scaling and often to outliers. Correlated features can make compression especially effective, but correlation is not a strict prerequisite for running PCA, nor does PCA prove causality. In cybersecurity, an attack indicator may vary rarely and thus have *low variance*; discarding a low-variance component could erase the very signal a detector needs. Evaluate downstream security performance, leakage, interpretability, and reconstruction errors before adopting a component count. PCA is also not a privacy guarantee: reduced coordinates may still reveal sensitive information.

## Section 12 of 24 — Anomaly Detection

Anomaly detection looks for observations that depart from a chosen notion of **normal**. It is often unsupervised because examples of every possible attack or failure are unavailable. HTB distinguishes a **point anomaly** (one unusual event), a **contextual anomaly** (unusual given its context, such as time of day), and a **collective anomaly** (a suspicious *sequence or group* whose members might each appear ordinary). These distinctions determine what features and observation window a detector needs. A per-login detector might miss a coordinated burst that only becomes visible after grouping logins by account, source, and time window. An alert is evidence for investigation, not a proof of malice.

HTB groups methods into **statistical**, **clustering-based**, and **machine-learning-based** approaches. A z-score or boxplot uses a distribution or spread model; a cluster method asks whether a point is far from or poorly represented by groups (Sections 9–10); a learned detector models normality more flexibly. The assumptions differ: a Gaussian z-score assumes a relevant roughly Gaussian feature distribution, while the three named algorithms below do not all require such a distribution. Feature scaling, feature choice, and the definition of a normal training period can change the result. Some methods or supervised variants require labels, but One-Class SVM and Isolation Forest can generally fit mostly-normal *unlabeled* examples; labels remain valuable for evaluation and threshold selection.

### One-Class SVM: a boundary around normality

The SVM in Section 8 separated **two labeled classes**. A **One-Class SVM** instead learns a boundary for a set intended to represent normal observations; points outside are candidates for investigation. A kernel can make this boundary nonlinear, just as in the earlier SVM lesson. The drawn “fence” is a useful metaphor, but its shape and false-alert rate depend on the kernel, parameters, training contamination, and feature representation. A malicious event that lands inside the learned normal region may be missed; a rare authorized action outside it may be flagged. This HTB section introduces the idea but does not give a One-Class SVM optimization equation, so the companion notebook does not invent one.

### Isolation Forest: unusual points take fewer splits

An Isolation Forest repeatedly chooses random feature splits to separate observations. A point that is **few and different** tends to be isolated after fewer splits than a point buried in a dense group. Unlike the Section 6 decision tree, an isolation tree does not pick splits to maximize label purity. HTB expresses a normalized score as `$s(x)=2^{-E(h(x))/c(n)}$`. Read it **“s of x equals two raised to the negative expected h of x divided by c of n.”** `$x$` is an observation; `$h(x)$` is its path length (number of splits before isolation); `$E(h(x))$` is the average path length across trees (say **“E of h of x”**); `$n$` is the dataset size; `$c(n)$` (say **“c of n”**) normalizes by a reference expected search-path length for that size. The minus sign in the exponent makes the score **decrease** as the path gets longer. The whole equation says: *short isolation paths produce larger anomaly scores, after adjusting for sample size*. The score is not the probability that an attack occurred.

For arithmetic only, pretend `$c(n)=10$`. If the average path length is `2`, then `$s(x)=2^{-2/10}=2^{-0.2}\approx0.871$`. If it is `10`, then `$s(x)=2^{-10/10}=0.5$`. The first point scores higher because it took fewer splits. The value `10` here is an **illustrative normalization factor**, not a claim that any particular dataset's true `c(n)` equals 10. HTB describes scores near 1 as more anomalous and near 0.5 as more normal; operational decisions still need a validated threshold and false-positive review.

### Local Outlier Factor: compare density *locally*

**Local Outlier Factor**, “L-O-F,” compares a point `$p$` with its `$k$` nearest neighbors. Say `$p$` **“point p”** and `$k$` **“the number of neighbors.”** The **k-distance of neighbor `$o$`** is the distance from `$o$` to its kth nearest neighbor. HTB defines `$\operatorname{reach\_dist}(p,o)=\max(d(p,o),\operatorname{kdist}(o))$`: read **“reachability distance from p to o equals the larger of their actual distance and o's k-distance.”** This floors an extremely short actual distance at the neighbor's local scale. For example, if `$d(p,o)=1$` and the k-distance of `o` is `3`, reachability distance is `3`; if actual distance is `5`, it is `5`. The `max` is a numerical operation, not a search for the most anomalous neighbor.

For the neighbor set `$N_k(p)$`, HTB's density formula is `$\operatorname{lrd}(p)=1/\left[(1/k)\sum_{o\in N_k(p)}\operatorname{reach\_dist}(p,o)\right]$`. Read **“local reachability density of p equals one divided by the average, across p's k neighbors, of reachability distance from p to each neighbor o.”** `$Σ$` (capital **“sigma”**) means add the following terms; `$o\in N_k(p)$` means **“o is in the set of p's k neighbors.”** The bracketed quantity is an average distance; taking its reciprocal makes larger distances correspond to smaller density. If two reachability distances are `3` and `5`, their average is `4`, so `lrd(p)=1/4=0.25`. A zero average would make this reciprocal undefined and needs deliberate handling in real implementations.

HTB then gives `$\operatorname{LOF}(p)=\left[(1/k)\sum_{o\in N_k(p)}\operatorname{lrd}(o)\right]/\operatorname{lrd}(p)$`. Read **“L-O-F of p equals the average local reachability density of p's neighbors divided by the local reachability density of p.”** The numerator asks how dense the neighbors' own surroundings are; the denominator asks how dense p's surroundings are. If two neighbor densities are `0.5` and `0.5`, their mean is `0.5`; with `lrd(p)=0.25`, LOF is `0.5/0.25=2`. The point is locally sparser than its neighbors. A value near `1` means similar local density; a value above `1` indicates increasing local isolation. These are **relative density ratios**, not probabilities. Density also depends on the distance metric, feature scaling, and `k`; isolated but uniformly sparse regions can behave differently from a single outlier next to a dense region.

The companion notebook checks exactly these arithmetic examples. It does **not** construct neighbors from a dataset, train a forest, or fit a One-Class SVM. In deployed security monitoring, establish a defensible normal baseline, keep preprocessing fixed between training and inference, measure false positives and false negatives on representative labeled reviews, watch for drift, and consider contamination or deliberate poisoning of the baseline. Context and collective behavior may require time-window and entity features; no scalar anomaly score alone establishes intent.

## Section 13 of 24 — Reinforcement Learning Algorithms

The earlier **supervised** examples learned from known input–label pairs; the **unsupervised** examples sought structure in unlabeled rows. **Reinforcement learning (RL)** instead studies repeated decisions. An **agent** chooses an **action** in its current **state**, the **environment** changes to a next state, and the agent receives a scalar **reward**. This cycle creates a sequence: today's action affects which states and opportunities exist tomorrow. The aim is not simply to choose the largest immediate reward; it is to choose actions that yield strong *cumulative* reward over time. HTB's dog-training and maze analogies illustrate feedback from experience, not a list of correct action labels supplied in advance.

### Say the loop in symbols and words

For a teaching shorthand, write a transition as `s_t --a_t--> s_(t+1), r_(t+1)`. Read `s_t` **“s sub t,” the state at time t**; `a_t` **“a sub t,” the action chosen then**; `s_(t+1)` **“s sub t plus one,” the resulting next state**; and `r_(t+1)` **“r sub t plus one,” the reward received after the action**. The complete shorthand says: *from this state, take this action; the environment responds with a new state and feedback*. The exact indexing convention varies across textbooks; the point is to keep the time ordering clear. This is an explanatory notation for HTB's verbal loop, not a formula quoted from the page.

A **policy** is a rule mapping a state to an action. Often written `π(a|s)`, read **“pi of a given s,”** it can mean the probability of choosing action `a` in state `s`; a deterministic policy always chooses one action for a given state. The symbol `π` is pronounced **“pie.”** A **state-value** asks how much total future reward we expect *starting in state s and following a policy*. An **action-value** asks how much we expect *after first taking action a in state s, then following the policy*. In common notation these are `V^π(s)` (**“V superscript pi of s”**) and `Q^π(s,a)` (**“Q superscript pi of s comma a”**). The expectation refers to uncertain transitions and any stochastic choices. HTB introduces their meaning, not an update rule for computing them; the notebook will not pre-implement a later RL algorithm.

Consider a two-step maze choice. One action yields `+3` now but leads to a dead end with no later reward. Another yields `0` now but reaches a goal worth `+10` one step later. A greedy immediate-reward rule chooses `+3`; a policy that sufficiently values the future may choose the goal path. A *reward* is the feedback signal defined by the task designer, **not** a guarantee that the action is safe or desirable outside the model. An agent can optimize an incomplete reward definition in unintended ways. In cybersecurity, a defender trained only to reduce alert count could learn to suppress alerts rather than improve protection. A security-testing agent might consume real resources or change systems while learning, so safe simulation and scoped, authorized actions matter.

### Gamma discounts later rewards

HTB's discount factor `γ` is pronounced **“GAM-uh”** and is usually between zero and one. As a tiny illustrative return calculation, `G = r_0 + γ r_1 + γ² r_2` is read **“G equals r sub zero plus gamma times r sub one plus gamma squared times r sub two.”** Each `r_i` is the reward at step `i`; `γ²` means **“gamma squared,”** so a reward two steps away is weighted twice by the discount. The whole equation says: *add future rewards, giving more distant rewards progressively less weight*. HTB explains the discount factor but does not present this full return equation; it is included solely to make the idea concrete. If rewards are `[0, 10]`, `γ=0.2` gives `0+0.2×10=2`, while `γ=0.9` gives `0+0.9×10=9`. With `γ=0`, only the immediate reward remains. With `γ=1`, finite-horizon rewards have equal weight; for an unending task, an undiscounted infinite sum may not be finite, so the page's simple statement about `γ=1` needs that qualification. Choosing gamma also changes how a delayed benefit compares with an immediate one.

**Model-based RL** learns or uses a model of how actions change states, then can plan with it—the maze map analogy. **Model-free RL** learns from experienced transitions without explicitly constructing that transition model. “Model-free” does *not* mean there is no learned policy or value estimate; it means no explicit predictive model of the environment is required for the decision method. Either approach can fail if the reward is mis-specified or training experience does not cover important states.

An **episodic** task ends at a terminal state: one maze run or one game ends and can be restarted. A **continuing** task has no natural end, such as ongoing equipment control. HTB calls the latter “continuous”; in RL literature **continuing** is often used to avoid confusion with continuous-valued states or actions. A terminal state matters for value calculations because there are no later rewards in that episode. The companion notebook computes discounted totals for a finite, invented reward list and shows why a future reward can outweigh an immediate reward. It does not interact with a live environment or train a policy.
